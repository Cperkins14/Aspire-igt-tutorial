How it works

What the simulation is doing under the hood.

The IGT deck structure (Bechara et al., 1994)
DeckWin per cardLosses per 10 cardsNet per 10 cardsType
A+$1005 losses totaling $1,250−$250Risky
B+$1001 loss of $1,250−$250Risky
C+$505 losses totaling $250+$250Safe
D+$501 loss of $250+$250Safe

Loss positions are shuffled within each block of 10 draws per deck, so runs are not identical. A player who always picks A or B ends around −$500. A player who always picks C or D ends around $4,500. If your results ever show a 100%-risky player finishing above $2,000, something is broken. Run the sanity check in Settings.

What happens each trial
  1. The tool builds a prompt with the profile, the trial number, the current balance, per-deck totals so far, and the most recent outcome
  2. If scratchpad mode is ON, the model writes one in-character sentence, then the deck letter on its own line
  3. The tool parses the letter (strict parse first, fallbacks logged), applies the real IGT payoff, and records everything including the raw model response
Troubleshooting
  1. Always run the payoff sanity check first. Never interpret model results on an unverified task.
  2. Check parse issues in the Results table. If a run shows many parse issues, the model isn't following the response format. Export raw responses and read them.
  3. If all profiles behave identically on a verified engine with clean parses, that is a real finding about the model, and it is now defensible.
